# Architecture

Polaris is a Go service built on **hexagonal architecture** (ports and adapters). The business
core depends on nothing; HTTP, PostgreSQL, and Prometheus are replaceable adapters behind ports.

```
                 ┌────────────────────────────────────────────┐
   Google ID ───▶│                                            │───▶ PostgreSQL 18.4
   X-API-Key ───▶│  httpapi adapter         postgres adapter  │      (system of record)
                 │  (REST + auth)           (store, outbox,   │
                 │                           schedules)       │
                 │         ▲            │                     │
                 │         │ inbound    │ outbound            │
                 │         │ ports      │ ports               │
                 │  ┌──────┴────────────▼──────┐              │
                 │  │     application layer    │              │
                 │  │  use cases (Service)     │              │
                 │  └──────────▲───────────────┘              │
                 │             │                              │
                 │  ┌──────────┴───────────────┐   prometheus │───▶ Prometheus HTTP API
                 │  │   domain/fitness         │   adapter    │     (instant + range queries)
                 │  │   aggregates, values,    │  (collector) │
                 │  │   evaluation, lifecycle  │              │
                 │  └──────────────────────────┘              │
                 └────────────────────────────────────────────┘
                          cmd/polaris — one process:
                          HTTP API + scheduled-collection worker
```

## Module map

| Import path | Responsibility |
| --- | --- |
| `internal/domain/fitness` | Aggregates, value objects, lifecycle rules, and deterministic evaluation. Pure Go — no I/O. |
| `internal/application` | Use cases and inbound/outbound ports (`Store`, `ScheduleStore`, `Collector`, `IDGenerator`, `Clock`). |
| `internal/adapters/httpapi` | REST receiver with Google OIDC and ingest API-key authentication. |
| `internal/adapters/postgres` | PostgreSQL persistence, embedded migrations, schedules, and a transactional outbox. |
| `internal/adapters/prometheus` | Provider adapter for instant and range PromQL queries. |
| `cmd/polaris` | Composition root: one process containing the HTTP API and the scheduled-collection worker. |
| `web` | React + TypeScript control tower for discovering and creating fitness functions. |
| `api` | The OpenAPI 3.0.3 contract (`openapi.yaml`), embedded in the binary and served at `/openapi.yaml`. |
| `gen/api` | Server bindings generated by oapi-codegen; CI rejects drift. |
| `migrations` | Embedded SQL migrations (run automatically, idempotent). |
| `tests` | Full-stack integration suites. |

## Design rules

- **Domain purity** — `internal/domain/fitness` imports nothing but the standard library. It owns
  lifecycle invariants and outcome calculation, which is what makes the 90% coverage and mutation
  gates meaningful.
- **Provider isolation** — provider-specific behavior stays behind the `Collector` port, so another
  adapter such as Grafana can be introduced without changing the fitness-function domain.
- **Spec-first API** — `api/openapi.yaml` is the source of truth. `make generate` produces
  `gen/api/server.gen.go`, and the CI `generated-code-drift` job fails if committed bindings differ
  from the spec.
- **Transactional outbox** — every state change and its domain event are written in the same
  PostgreSQL transaction (`CreateRecord`, `SaveFitnessFunction`,
  `SaveSubmissionAndEvaluation`). Consumers `POLL` events and acknowledge explicitly; delivery is
  at-least-once.
- **Single process, two roles** — `cmd/polaris` serves the HTTP API and ticks a worker
  (`RunScheduledCollections`) that claims due pull collections.
